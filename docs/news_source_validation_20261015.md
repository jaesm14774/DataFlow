# 新聞來源擴充與修復驗證

狀態：本次擴充與修復已完成，15 來源已經自然排程正式入庫，數量與欄位驗證通過。瀏覽器實際核對 13 來源；ETtoday、三立的瀏覽器存取限制另列，未冒稱驗證通過。目前未提交 commit，保留工作區原有修改。

## 擴充與修復

啟用來源由 12 個增加為 15 個，已接入 `news_ch_collect_process` 原有的收網址、解析文章、正式入庫三個任務。新增來源與驗證範圍：

| 新來源 | 收集方式 | 實測完整文章 | 題材與分類 |
| --- | --- | ---: | --- |
| 泛科學 | 官方 RSS＋原文頁 | 10 | 醫療健康、科學儀器、科技能源；保留原文全部分類 |
| 報導者 | 官方 RSS＋公開全文 | 10 | 政治社會、人權司法、評論、Podcast |
| 環境資訊中心 | 新聞、評論、專欄、副刊四種列表＋原文 | 48 | 生態、氣候、減碳、自然書寫、攝影、環境書摘 |

新增來源會帶回部分舊文章，這些是該站目前公開列表／RSS 中的內容，沒有把抓取時間冒充發布時間。泛科學 RSS 以醫療內容為主，不能單獨代表所有科學領域；題材多樣性由整體 15 來源與各站原始分類共同提供。

| 問題 | 現場證據與修正 |
| --- | --- |
| 鉅亨錯誤標題、空分類 | 第一個 h1 可能是 `...` 占位文字；改讀與文章網址匹配的 NewsArticle、發布時間及麵包屑分類 |
| 自由娛樂／健康／評論正文空白 | 隱藏空模板先於實際正文、子站 wrapper 不同；改選有文字的實際文章區域，排除閱讀提示 |
| 三立健康／房產文章被略過 | 子站缺少主站 JSON-LD、健康標題使用 `.newsTitle`；支援子站正文與可見日期，仍要求列表相對時間佐證以免把錯誤 Z 時區加八小時 |
| TVBS 中文亂碼與標題截字 | HTTP 預設文字編碼錯誤；改由原始 bytes 解析。標題移除精確尾綴，避免 `strip` 刪除合法字元 |
| ETtoday 分頁無上限 | 加入頁數上限、POST timeout、HTTP 檢查、重複與空頁停止；每次呼叫重新計算台北日期 |
| ETtoday 分類含整段網站導覽 | logo 區曾把 ETtoday、空白行與 GO 一起當分類；現在隔離唯一分類標籤，優先文章分類 metadata／選取分類，沒有可靠標籤時保留列表分類。已備份並修正一筆近期入庫的實際案例，發布時間與入庫時間均保留 |
| 來源時間與文章不一致 | 中央社、中時、聯合、關鍵評論優先使用文章發布 metadata；保留缺乏精確時間的日期精度 |
| 聯合轉址頁摘要被當成全文 | 原頁無正文，瀏覽器以明確 JavaScript literal 導向公開全文；程式曾把 50 字 og:description 當正文。現在僅辨識文章 wrapper 內的限定 UDN 公開網址轉址，最多兩次轉址；完整正文、實際 ID、網址與發布時間一起核對，不執行腳本，也不以摘要補全文 |
| 報導者無法入庫 | 自然排程出現 `Data too long for column article_id`；三張表均為 varchar(50)。改用完整 canonical path 的固定 49 字元 SHA-256 衍生 ID，原始網址完整保留 |
| 非正文／錯誤資料混入 | 新增占位標題、錯誤頁、亂碼、空內文、無效與未來時間檢查；拒收原因、分類與來源計數寫入 XCom，並維持拒收數量核對 |

RSS 新來源另外核對 redirect 與 canonical 網址，避免把另一篇文章綁到原文章 ID。泛科學限定第一篇公開文章 wrapper，避免把後續推薦文章抓進正文。
